# Схема базы данных InterVUZ

База данных рассчитана на PostgreSQL.

## Основные сущности

- `users` — пользователи приложения: студенты, преподаватели, сотрудники, администраторы.
- `campuses` — кампусы или крупные площадки вуза.
- `buildings` — корпуса внутри кампуса.
- `places` — точки навигации: аудитории, кафедры, столовые, деканаты, принтеры, библиотеки и другие объекты.
- `routes_cache` — кэш заранее посчитанных маршрутов между точками.

## Расписание

- `academic_groups` — учебные группы.
- `teachers` — преподаватели.
- `disciplines` — дисциплины.
- `schedule_sources` — источники импорта расписания пользователя или группы.
- `schedule_events` — пары и другие события расписания.
- `schedule_event_groups` — связь many-to-many между событием и группами.
- `schedule_event_teachers` — связь many-to-many между событием и преподавателями.
- `schedule_event_audiences` — нормализованные аудитории из групповых расписаний для поиска занятости.
- `room_bookings` — брони аудиторий на конкретные интервалы времени.

## Ключевые решения

- Для идентификаторов используется `uuid`.
- Аудитории хранятся в `places`, чтобы навигация и расписание ссылались на одну сущность.
- Учебные события нормализованы через отдельные связи с группами и преподавателями, потому что одна лекция может относиться сразу к нескольким группам.
- Бронь аудитории длится 90 минут; пересекающиеся брони одной аудитории запрещены constraint-ом в PostgreSQL.
